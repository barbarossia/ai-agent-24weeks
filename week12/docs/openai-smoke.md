# Authenticated smoke through Codex App Server

Protocol reference: [official Codex App Server documentation](https://learn.chatgpt.com/docs/app-server). Process-local settings follow the [official configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference). Protocol fields were also checked against JSON schemas generated by local `codex-cli 0.155.0-alpha.16.3`. An incompatible CLI should be treated as a blocker, not a reason to use an undocumented endpoint.

1. Install dependencies with `uv sync --dev` from `week12`. Confirm the existing Week 11 read-only connection is available through the environment described in README. Select an existing sanitized note's exact source identity. Week 12 must not create data to make this test pass.
2. Run `uv run python -m homelab_knowledge_agent auth-status`. Only managed ChatGPT mode is accepted. No account email, token, login URL or raw server response is printed.
3. If login is unavailable, stop automation for the account owner to complete the supported Codex ChatGPT sign-in (`codex login`, choose ChatGPT). A custom client can use documented `account/login/start` with `type: chatgpt`, display its returned browser URL to the user, and wait for `account/login/completed`. This project does not automate that interactive login. Never extract browser tokens or switch to API keys/external-token authentication.
4. Once configuration and auth are available, run the exact README command:

   ```powershell
   uv run python -m homelab_knowledge_agent ask "What should I check when my HomeLab datastore is unhealthy?" --model gpt-6-sol --source-path integration-test/week12-demo/note.md
   ```

   The named identity must already exist, or replace it with the chosen sanitized source. Choose another explicitly available OpenAI Codex model if this account cannot use the example; there is no automatic fallback. The Week 8 subprocess is always forced to MockAdapter even if the parent environment requests OpenWrt.

5. Verify that the resulting answer combines a retrieved fact with current-request mock health, includes the exact source path/heading (subject to documented length caps), and states that the MCP response is MockAdapter sample data, not real-device readings. Embedded health timestamps are sample values; `fetched_at` indicates when the MCP call ran. No matches means the retrieval portion is unverified.
6. Record command, CLI version, exit status, pass/blocker and sanitized observations only. Do not capture raw JSON-RPC, server stderr, tokens, auth URLs, full environment, connection values or private note text. An auth-status pass only confirms recognized authentication; model authorization/network/quotas still need the actual generation turn.

Exit code 0 means the command completed; 2 means a named integration blocker; 1 is a redacted unexpected failure. Missing read-only DB configuration stops before MCP/model execution. Auth failures stop before a thread/turn. App Server request timeout is 30 seconds and generation completion timeout is 120 seconds. No alternative provider is attempted and no DB/container setup is performed.
